# UGC Moderation Service

Сервис принимает текст комментария и возвращает решение модерации: `ALLOW`, `REVIEW` или `BLOCK`.

Модель: TF-IDF (символьные n-граммы) + логистическая регрессия,
обучена на [Mnwa/russian-toxic](https://huggingface.co/datasets/Mnwa/russian-toxic).
Разметка бинарная, поэтому причины блокировки по категориям вне скоупа.

## Требования

Python 3.10.11, опционально docker.

## Установка

```bash
pip install -r requirements-dev.txt
```

Для запуска только сервиса достаточно `requirements.txt`.

## Обучение

Перед первым запуском сервиса модель надо обучить.

```bash
python src/train.py
```

Создаёт `models/model.joblib`, `data/valid.jsonl` и `data/test.jsonl`. Занимает пару минут.

Сейчас модель и датасеты есть в репозитории в гите, в настоящем сервисе стоит хранить в dvc.

## Метрики

```bash
python src/eval.py [--model-path PATH] [--test-path PATH] [--metrics-path PATH]
```

Считает метрики по сохранённой модели на test, пишет результат в `data/metrics.json`.
Метрики привязаны к фактическим порогам сервиса, а не к абстрактному 0.5:
доли зон, загрязнённость ALLOW, precision / recall / FPR для BLOCK, плюс ROC-AUC.

## Выбор порогов

Подбор — в `notebooks/thresholds.ipynb`, на отложенной valid-выборке (20% от train).
Test не используется, иначе финальные метрики окажутся завышенными.

Ограничения, из которых считались пороги:

- FPR блокировок < 0.5% — ложная блокировка в дискуссии дороже пропущенного
  хамства, которое отлавливается жалобами
- доля токсичных среди автопубликуемых < 1%
- ручная модерация < 10% потока.

Метрики пересчитаны под ожидаемую долю нарушений в реальном потоке (5%), а не
под баланс датасета (21%): precision зависит от базовой ставки, и без пересчёта
оценка получается завышенной. FPR и TPR от неё не зависят, поэтому ограничение
на BLOCK задано именно через FPR.

Результат:

```
ALLOW_BELOW=0.33
BLOCK_ABOVE=0.88

  ALLOW  86.4%, из них токсичных 0.38%
  REVIEW 9.7%
  BLOCK  3.9%, precision 88.16%, recall 68.85%, FPR 0.487%
```

Связывающими оказались два ограничения: FPR снизу и бюджет модераторов сверху.
Лимит загрязнённости выполняется с запасом (0.38% при допустимом 1%) —
при базовой ставке 5% токсичного в потоке слишком мало, чтобы зона ALLOW
загрязнилась сильнее, поэтому на выбор порогов этот лимит не влияет.

## Тесты

```bash
pytest
```

Проверяют контракт API, валидацию входа и границы зон.
Требуют обученной модели.

## Запуск

```bash
uvicorn src.app:app --host 0.0.0.0 --port 8080
```

Docker (сначала обучение — образ копирует готовую модель):
```bash
docker build -t moderation .
docker run --env-file .env -p 8080:8080 moderation
```

## API

```bash
curl -X POST localhost:8080/moderate \
  -H 'Content-Type: application/json' \
  -d '{"text": "привет, отличная статья"}'
```

```json
{"decision": "ALLOW", "confidence": 0.03}
```

- `decision` — `ALLOW` / `REVIEW` / `BLOCK`
- `confidence` — вероятность токсичности, 0..1
- текст: 1–5000 символов, иначе `422`

`GET /health` — стандартный хелсчек. Документация: `/docs`.

## Конфигурация

Читается из переменных окружения, для локального запуска — `cp .env.example .env`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MODEL_PATH` | `models/model.joblib` | путь к модели |
| `ALLOW_BELOW` | `0.3` | ниже порога — `ALLOW` |
| `BLOCK_ABOVE` | `0.8` | выше порога — `BLOCK` |
